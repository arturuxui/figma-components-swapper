# Составные компоненты — опыт этапа 2в (2026-10-09)

Правило 32 скилла: фрейм со своим оформлением (заливка, обводка, эффект), внутри которого лежат компоненты, может
быть нашим составным компонентом под другим именем (пример скилла: `Booster` → `Booster Section`).

## Что есть в библиотеке

Составные компоненты Driver Components (варианты, внутри которых есть компоненты крупнее иконки), снято из файла
библиотеки: `bar/button` (2–3 `balance`), `alert` (кнопки `wide` / `set`), `price` (`fab/primary`), `tarif`
(`medium/mono`), `options`, `navigation` (`center` + `Route Progress`), `order` (`small`), шапки `center` / `small`
(`search`, `Tabs`), `selector` (`Divider`), `address` / `comment` (`comment`), `adresses/offer`, `adresses/order`,
`set`, `wide` / `big` / `floating` (`Motivation`), `review` (`progress`), `Tabs` (`Tab`), ` StatusInfo`
(`statusbar`), `instruction/rounded`, `ActiveOrderClientView`, диалог `default`. Всего около 25.

## Правило (`src/core/composite.ts`)

Проверяется в подборе ручного фрейма (2б) последним — после «Имя и устройство» и «Похож по устройству»:

1. У фрейма своё оформление и хотя бы один вложенный компонент крупнее иконки.
2. Вариант нашего компонента подходит по размеру (±20 %).
3. **Все** вложенные компоненты фрейма есть в варианте (по имени, с повторами), и общих — не меньше половины
   большего списка: `wide` из `wide + wide` — да, `balance ×3` в `balance ×2` — нет (одна потерялась бы).
4. Устройство похоже ≥ 70 % (как у «Имя и устройство»).
5. Порядок кандидатов: сначала имя фрейма с суффиксом составного (`Booster` → `Booster Section`, суффиксы из
   скилла + `panel`), потом похожесть.

Статус «Составной»; сразу не выбран — примерка и решение дизайнера; замена — как у 2а/2б (`replaceFrame`).

Устройство библиотеки — тот же снимок, что в опыте 2б (206 вариантов). Страницы «✈️ Port queue» (368 кандидатов),
«👑 Main Screen» (95), «📍 Order» (37).

### Две ошибки, найденные прогоном (исправлены и в 2б)

1. **Группа судилась по первому фрейму.** Три `balance panel/1. three items` одного размера попадали в одну группу,
   а пару группа подбирает по первому фрейму — устроенному иначе. Теперь в группу ручных фреймов входят только
   фреймы с одинаковым именем, размером **и устройством** (`groupManual`).
2. **Кандидаты в скрытых секциях.** Два из трёх `balance panel` лежат в скрытых секциях `Misc` и `Original` — в
   макете их не видно. Теперь ручные кандидаты ищутся только там, где видны все родители (`scanNodes`).

## Замена на копии

Страница «Components Swapper · Composite» (`4463:23144`) в «🚕 New Driver DEV 🚀»: копии экрана `layers`
(«✈️ Port queue», секция Old City) и экрана `Narrow Screen Example` («📍 Order»). Код плагина (`applySwaps`):

- заменено 2 из 2, 0 потерянных текстов, 0 ошибок; отмена вернула 2 из 2 (отдельный прогон);
- `bar/button` → вариант `Buttons=3 buttons, Type=Main`, тексты «Меню / Предзаказы / Новости» на месте;
- `tarif` встал в auto layout шторки на место `badges`, текст «Эконом» на месте; иконки опций потеряны —
  примерка показывает это заранее.

Результат оставлен на странице для проверки инженером (иконки в прогоне не подбирались — индекс иконок в нём не
передавался; в плагине подбираются по имени).

**Находка для этапа 5:** у `tarif` нет места для иконок опций заказа (животные, детское кресло, аэропорт).

## Ограничения

- Составные пары нашлись редко (2 на 500 кандидатов): в этих файлах составные обычно уже экземпляры.
- Имена вложенных компонентов сравниваются после замены этапа 1 или по совпадающему имени старого компонента;
  если старый компонент назывался иначе, фрейм не узнаётся — сначала этап 1, потом пересканировать.
