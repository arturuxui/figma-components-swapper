## Что в плагине

В макете, до скана, — карточка «Замер внедрения AID»: выбор страниц файла, продукт (угадать / driver / rider),
«Замерить». Итог — таблица AID / Старая / Локальные / Другие для компонентов и иконок, отдельно скрытые; «готово к
замене»; JSON точки строго §5 (только счётчики) — «Скачать JSON» и «Копировать». Макет не меняется.

Код: `src/core/adoption.ts` (правила, без Figma API, тесты `tests/adoption.test.ts`), `src/figma/measure.ts` (обход
страниц), `src/ui/Measure.tsx`.

## Правила и расхождения с методикой (решения инженера 2026-10-22)

| Правило | Методика / аудит | В плагине |
|---|---|---|

**Совпадение или объяснённое расхождение — по всем пяти:**
- **Main Screen** — совпадает до экземпляра по всем столбцам.
- **Where, Order** — плагин совпадает со скриптом аудита сегодня; от 13.10 расходятся, потому что макеты с тех пор
  правили (Where −149 экземпляров, Order +595). Тот же скрипт аудита на той же странице сегодня даёт новые числа.
- **Navigation** — без наборов компонентов плагин даёт 10 946, как аудит 13.10 (скрипт аудита сегодня — 10 949, на
  3 больше, не разобрано, 0,03 %); +351 — экземпляры внутри наборов компонентов на странице, их плагин считает.
- **Components** — страница — локальная мини-библиотека, почти всё в наборах. Аудит 13.10 (737, старая 109 —
  совпадает) их, судя по числам, считал, а его сохранённый скрипт сегодня в наборы не заходит (300). Плагин — 744:
  разница с 13.10 — +7 локальных и +1 скрытый.

**Уникальные с аналогом** отличаются от аудита по смыслу, а не по ошибке: аудит искал аналог свободно (последний
сегмент имени, без `ic`, по обоим продуктам) и считал скрытые и иконки; плагин — только видимые компоненты своего
продукта с уверенной парой по имени и размеру. Например, Main Screen: аудит 61 / 53, плагин 36 / 28.

## Старая библиотека или прочие (2026-10-23)

Решение PD (#280, `external-repo-standards` §8): старые библиотеки продукта — `figmaLegacyLibraries` в
`products/<id>/product.json` репозитория AID; наш PR RickOBrian/aid#347 вносит «🔥 DS Ui Kit»
(`IpBYXW1UD5m2eQA8XwU4Sq`) и «📖 DS Icon & Illustration» (`6FjhiobrmMZmzBrkox0j3y`) — общие для Rider и Driver; к
остальным старым библиотекам у инженера нет доступа. Plugin API не говорит, из какого файла компонент, поэтому
плагин, как с библиотеками AID, собирает **индекс старой библиотеки** в её файле (`config/libraries.json`, `kind:
"legacy"`): только ключи наборов и отдельных компонентов — экземпляр узнаётся по ключу набора, варианты не нужны.
Размер: «🔥 DS Ui Kit» — 678 ключей вместо 7 745 компонентов (5 665 — варианты кнопки), «📖 DS Icon & Illustration» —
2 061. Индексы старых библиотек в подбор и в «наше» не идут.

В замере: внешний из старой библиотеки — `legacy`, прочий внешний — `other`; «готово к замене» — только по `legacy`
(методика §1). Нет индексов старых библиотек — как раньше (всё внешнее `legacy`), окно предупреждает.

Проверка по ключам (только чтение): старые иконки макетов `24/Fill/…`, `24/Stroke/…` — из «📖 DS Icon &
Illustration»; самые массовые старые компоненты Rider (`service`, `floating`, `address`, `mid`, `small`) — ни в
одной из двух: после сборки индексов они уйдут в `other`, `legacy` и «готово к замене» у Rider заметно уменьшатся.
Это честный счёт по списку PD, а не ошибка.

Риск: «🔥 DS Ui Kit» у нас только на чтение; один раз Figma ответила на загрузку всех страниц «попытка изменить файл
в режиме только чтения», по одной странице — читается. Поэтому сборка индекса теперь грузит страницы по одной.

### Снимок ключей и копии из других файлов (2026-10-23)

- **Плагин в старых библиотеках не запустить:** у инженера к «🔥 DS Ui Kit» и «📖 DS Icon & Illustration» только
  просмотр. Поэтому ключи снимает Claude чтением через use_figma и кладёт в `config/legacy-keys.json` (первые 8 знаков
  ключей наборов и отдельных компонентов, 678 + 2 061, снимок от 2026-10-23). Собранный индекс, если появится, важнее
  снимка. Обе библиотеки живые: компоненты, добавленные после снимка, попадают в «Другие» до обновления снимка —
  обновлять перед замером для PD. Дальше — ключи с сервера Library Updater (запрос через Штаб).
- **Копии из других файлов.** Массовые старые компоненты Rider (`service`, `floating`, `address`, `Map`) по ключу не
  подгружаются: их нет ни в одной опубликованной библиотеке, доступной инженеру, — это копии из других файлов
  (инженер: «могут быть подхвачены из локальных .fig-файлов»). Старая `ic_menu` подгружается — есть ещё хотя бы одна
  доступная старая библиотека иконок, не из списка. В замере копии — в «Другие» (не из старой библиотеки продукта),
  в окне — отдельной цифрой: плагин пробует подгрузить каждый уникальный внешний компонент по ключу (подгрузка не
  меняет макет на холсте; в файле только на чтение она запрещена — тогда цифры нет). Куда относить копии по
  методике — вопрос к PD.
