# Этап 3: иконки по рисунку — свой модуль и замер против подхода Token Comparator

Решение инженера (2026-10-21, через Штаб, AID-LU-9): изучить подход Token Comparator, написать свою реализацию
отдельным модулем, сравнить цифрами. PD предупреждён в RickOBrian/aid#185, решение по общему модулю — за ним.
Код TC только прочитан (`tools/figma-token-comparator/src/lib/icon*.ts`), не взят.

## Подход TC (как понял по коду)

Рисунок иконки (все видимые слои) растеризуется в маску 32×32 «закрашено / нет» (клетка закрашена, если внутри
2 из 4 проб); рисунок вписывается в квадрат по центру с сохранением пропорций. Похожесть — доля совпадения масок.
≥ 0.97 — та же форма, 0.85–0.97 — похожая, ниже — по форме не предлагается. Двойники (≥ 0.99) разводятся по размеру
рисунка, прозрачности, имени. Цвет — из макета, но только у одноцветной иконки; многоцветная остаётся в цветах
библиотеки (решение PD).

## Свой модуль

- `src/core/icon-shape.ts` (без Figma API): путь SVG → ломаные → **сетка 32×32 с долей закраски** (16 проб на
  клетку, сканлайном), похожесть — **Σmin / Σmax с допуском сдвига на 1 клетку**; подбор `rankIcons` (быстрый отбор
  без сдвига, сдвиг — для 12 ближайших), двойники — по размеру рисунка, потом по имени; **одноцветной иконке
  многоцветные не предлагаются**; хранение отпечатка в 684 знака (свой base64 — в песочнице нет btoa). Интерфейс —
  `printIcon` / `iconSimilarity` / `rankIcons`: его можно заменить общим модулем.
- `src/figma/icon-geometry.ts`: пути рисунка из узлов (заливка/обводка видимых фигур, булева операция — целиком,
  фон контейнеров не рисунок), цвет иконки (`iconColor`: многоцветная или цвет для переноса).

Пороги: ≥ 0.9 — та же форма, 0.75–0.9 — похожая (решает дизайнер).

## Замер

Скрипты — `.claude/cs-test/icon-eval.ts`, `icon-sheet.ts`, `icon-tune.ts` (не в git). Способ TC воспроизведён по
описанию (маска 2 из 4 проб, доля совпадения, 0.97 / 0.85, двойники — по имени).

**Driver** («New Driver DEV», Port queue и Main Screen): иконки старой библиотеки нарисованы так же, как наши —
оба способа нашли 86 из 86 одноимённых (рисунок 1.00). Различий нет.

**Rider** («New Rider DEV», Where, GEO Problems, Navigation): иконки из другой библиотеки (`24/Stroke/…`,
`24/Fill/…`) — рисунок другой. Лист проверки со снимками (страница «Components Swapper · Иконки по рисунку
(проверка)», 108 разных иконок); правильный ответ размечен глазами для 44 трудных (одноимённые с тем же рисунком —
не в счёт).

| | Нашли верную пару (из 30, где она есть) | Неверная пара | Ложная пара, где пары нет (из 14) |
|---|---|---|---|
| **Наш (доля закраски + сдвиг + правило цвета)** | **22 (73 %)** | 4 | 2 |
| Наш + сравнение краёв (опыт) | 21 | 4 | 0 |
| Подход TC | 16 (53 %) | 3 | 1 |

Точность предложений одинаковая (≈ 79–80 %), а находит наш на треть больше: `search`, `steeringWheel` → `ic_wheel`,
`pinFill` и `Icon / Adresses / Pin` → `ic_set_on_map`, `medicineCaseFill` → `ic_business`, `ic_arrow_right`
другой библиотеки. У TC они ниже порога 0.85: маска «закрашено / нет» сильнее штрафует другую толщину линии.

Не решено обоими: заливные иконки на круге (`timeFill`, `warningFill`, `Icon / Adress`) уходят к монете
`ic_citycoin_color` или к «i»/«+» в круге — детали внутри круга на сетке 32×32 почти не различаются; сравнение краёв
это не исправило и потеряло простой случай (`ic_default`), поэтому не взято. Пропуски обоих: `Pencil`, `Options`,
`ic_schedule`, `▶ icon` (refresh) — рисунок у нас другой.

**Цвет.** Из 45 размеченных иконок макета 33 одноцветные — им переносится цвет макета; 12 многоцветных (машинки,
платёжные, кольцо адреса) — остаются в цветах библиотеки, и им предлагаются и многоцветные наши.
