# Этап 3: иконки по рисунку — свой модуль и замер против подхода Token Comparator

Решение инженера (2026-10-21, через Штаб, AID-LU-9): изучить подход Token Comparator, написать свою реализацию
отдельным модулем, сравнить цифрами. PD предупреждён в RickOBrian/aid#185, решение по общему модулю — за ним.
Код TC только прочитан (`tools/figma-token-comparator/src/lib/icon*.ts`), не взят.

## Подход TC (как понял по коду)

Рисунок иконки (все видимые слои) растеризуется в маску 32×32 «закрашено / нет» (клетка закрашена, если внутри
2 из 4 проб); рисунок вписывается в квадрат по центру с сохранением пропорций. Похожесть — доля совпадения масок.
≥ 0.97 — та же форма, 0.85–0.97 — похожая, ниже — по форме не предлагается. Двойники (≥ 0.99) разводятся по размеру
рисунка, прозрачности, имени. Цвет — из макета, но только у одноцветной иконки; многоцветная остаётся в цветах
библиотеки (решение PD).

## Свой модуль

- `src/core/icon-shape.ts` (без Figma API): путь SVG → ломаные → **сетка 32×32 с долей закраски** (16 проб на
  клетку, сканлайном), похожесть — **Σmin / Σmax с допуском сдвига на 1 клетку**; подбор `rankIcons` (быстрый отбор
  без сдвига, сдвиг — для 12 ближайших), двойники — по размеру рисунка, потом по имени; **одноцветной иконке
  многоцветные не предлагаются**; хранение отпечатка в 684 знака (свой base64 — в песочнице нет btoa). Интерфейс —
  `printIcon` / `iconSimilarity` / `rankIcons`: его можно заменить общим модулем.
- `src/figma/icon-geometry.ts`: пути рисунка из узлов (заливка/обводка видимых фигур, булева операция — целиком,
  фон контейнеров не рисунок), цвет иконки (`iconColor`: многоцветная или цвет для переноса).

Пороги: ≥ 0.9 — та же форма, 0.75–0.9 — похожая (решает дизайнер).

## В плагине

- **Индекс иконок** (собирается в файле библиотеки) хранит отпечаток каждой иконки, размер рисунка и
  многоцветность (`IndexEntry.icon`). Старый индекс иконок без отпечатков работает как раньше, в окне подсказка
  «пересоберите, чтобы подбирать по рисунку».
- **Подбор:** если по имени уверенной пары нет, иконка размером до 48 px сравнивается по рисунку (`matchIcon`):
  «Тот же рисунок» (≥ 0.97, выбор однозначен, обе одноцветные) — заменится сама; «Похож по рисунку» — решает
  дизайнер, в списке ближайшие. Многоцветную по одному силуэту сама не заменяет (прогон: кольцо адреса совпало
  силуэтом с цветной монетой на 100 %).
- **Цвет из макета:** при замене одноцветной иконки её цвет переносится на нашу (`paintIcon`), прозрачность частей
  нашей иконки сохраняется; многоцветная наша остаётся в своих цветах.
- **Актуальность отпечатков.** Иконки в библиотеке меняются, удаляются, добавляются. При каждом скане плагин
  подгружает из библиотеки все иконки, которые собирается предложить (актуальная опубликованная версия), и сверяет
  рисунок с индексом: перерисованная — подбор по новому рисунку, удалённая — из подбора убирается; в окне —
  «Индекс иконок устарел: перерисованы …, удалены … — пересоберите». Новые иконки так не найти: Plugin API не
  перечисляет библиотеку, их приносит только пересборка индекса (или свой сервер с REST API Figma — позже).

Прогон на копии страницы Navigation (New Rider DEV, «Components Swapper · Иконки по рисунку (замена на копии
Navigation)»): индекс 172 иконки с отпечатками, 18 групп иконок, сверено 38 предложенных — изменённых нет;
86 замен без ошибок, цвет макета на месте.

## Проверка после пополнения библиотеки (21.10, вечер)

Инженер пересобрал индексы; в библиотеке иконок Rider 236 иконок (было 176): +62 новых, −2
(`ic_favorite_wb_shape`, `ic_ride_experience`), часть переименована с припиской вида (`ic_add_circle` →
`ic_add_circle_fill`, `ic_call` → `ic_call_fill`, `ic_trash` → `ic_trash_fill`…). Прогон на 6 страницах New Rider DEV
(Where, GEO, Navigation, Service coverage, Taxi for friends, Permissions; 288 мест с иконками), только чтение:

| | Старая библиотека | Новая | Новая + правки |
|---|---|---|---|
| Пара по имени | 46 | 29 | 29 |
| Тот же рисунок (замена сама) | 25 | 25 | 22 |
| Похож по рисунку (решает дизайнер) | 120 | 127 | 198 |
| Нет пары | 93 | 107 | 39 |

Новые иконки сами по себе почти ничего не дали, переименования сломали пары по имени. Что мешало и что исправлено
(решение инженера — все три одним PR):

1. **Пустой пример группы.** Рисунок брался у одного экземпляра; у `ic_add_circle`, `chevronDownSmall`, `Rating Star`
   и других экземпляры скрыты и без слоёв. Теперь — первый экземпляр с рисунком, а если пусты все — главный
   компонент. Это дало больше всего: −60 мест «нет пары».
2. **«Icon / X» и «ic_x» — одно имя.** Имена иконок сравниваются без пути, приставок `ic_`/`Icon`, размера и приписки
   вида (`_fill`, `_outline`, `_color`…): «Icon / Adress» → `ic_adress` (0.80), «Icon / Surge» → `ic_surge` (0.71),
   «natural main» → `ic_natural_main` (0.83), `ic_add_circle` → `ic_add_circle_fill` (0.92).
3. **Одноимённая — первой**, если рисунок хоть немного похож (≥ 0.65), даже когда чужой ближе: `ic_wait` 16 px →
   наш `ic_wait` (0.86), а не `ic_parking` (0.89). Это всегда «похож» — решает дизайнер; поэтому «Icon / Plus»
   (5 мест) больше не заменяется сама на `ic_plus_mini` (0.99), а предлагает `ic_plus` (0.89) первой.

Осталось без пары: `Car`, `Car Class` (картинки машин), «Icon / Options», «Counter notification» — у нас таких иконок нет.
