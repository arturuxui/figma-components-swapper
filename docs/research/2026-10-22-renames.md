# Карта переименований библиотек (AID-LU-18) — сторона Swapper

Задача из Штаба (решение инженера 2026-10-22 «разложи пункты 1 и 3 в задачи»). Источник — сервер Library Updater:
при каждой публикации библиотеки он сравнивает опубликованное по ключу. Контракт — PR
arturuxui/figma-library-updater#41:

`GET https://library-updater.wb-aid-lu.workers.dev/libraries/<id|fileKey>/renames?since=<ISO>` → `{ entries, cursor }`;
запись — `{ id, libraryId, fileKey, publishedAt, by, description, renamed[{kind,key,from,to,setKey?,setName?}],
deleted[…], added[…] }`; заголовок `X-Figma-User-Id` = `figma.currentUser.id`; CORS `*`.

## Что делает плагин

- При скане для каждой библиотеки с индексом запрашивает новое с прошлого курсора (первый раз — всю историю) и
  хранит карту в `clientStorage` (`src/figma/renames.ts`). Сервер не ответил за 5 с или с ошибкой — работает по
  сохранённой карте или без неё, как раньше.
- **Переименования** (`src/core/renames.ts` → `buildCandidates`): наш компонент или набор подбирается под всеми
  именами, что у него были. Старое имя в макете («ic_add_circle») — точная пара с нашим под новым
  («ic_add_circle_fill»); это раньше правил `_fill/_outline` из подбора по рисунку. Варианты наборов не берутся: их
  переименование — смена значения оси.
- **Удалённые после сборки индекса** — из подбора убираются, в окне предупреждение с именами.
- **Добавленные после сборки индекса** — в окне «добавлено N — пересоберите индексы» (новое плагин видит только
  из индекса).
- Манифест: `networkAccess.allowedDomains` — сервер LU, `permissions: ["currentuser"]` — для заголовка.

  даты индекса.

  карты ещё не развёрнут (404) — плагин в этом случае работает без карты.
