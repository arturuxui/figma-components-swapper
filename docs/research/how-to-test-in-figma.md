# Как проверять код плагина в Figma без инженера

Способ, которым проверены этапы 0–2: собрать нужные модули плагина в один скрипт и выполнить его в файле через
`use_figma` (сервер Figma MCP, коннектор Figma в Claude). Так проверяется настоящий код плагина, а не
переписанный, — но без его окна и без `clientStorage`.

## Порядок

1. Загрузить скилл `figma:figma-use` (обязательно перед `use_figma`).
2. Точка входа — файл во временной папке (scratchpad), импорты из проекта **абсолютным путём Windows**
   (`'D:/Claude Code Workplace/Figma Plugin - Components Swapper/src/…'`; путь `/d/…` esbuild не понимает).
   Экспортировать функцию `run(...)`.
3. Собрать: `npx esbuild <entry>.ts --bundle --minify --charset=utf8 --format=iife --global-name=CS --target=es2020 --outfile=<out>.js`.
   Можно собирать и модуль проекта напрямую (`src/figma/replace-frame.ts` → глобальное `RF`).
4. Код для `use_figma` = содержимое сборки + `return await CS.run(...)`. Данные (индекс, ключи) — строкой в
   конце скрипта.
5. Писать в макет — только на копии на отдельной странице «Components Swapper · …» (правило инженера), чтение —
   где угодно. Файлы библиотек — только читать.

## Ограничения среды `use_figma`

- Код — до 50 000 знаков, ответ — до 20 КБ (больше — ошибка, изменения не сохраняются).
- Одна страница на вызов: `await figma.setCurrentPageAsync(page)` один раз; несколько страниц — параллельными
  вызовами. `loadAllPagesAsync` не поддерживается — поэтому `buildLibraryIndex` целиком здесь не запустить, индекс
  собирается по страницам (скрипт `shapesOfPages` — устройство вариантов; ключи — `findAllWithCriteria`).
- `figma.commitUndo` и `setPluginData` не поддерживаются: в коде плагина они обёрнуты в `try` — так и должно
  оставаться.
- Обращение к несуществующему свойству узла бросает исключение (`node.error`) — не проверять так «ошибку».
- Журнал отмены живёт в памяти одного вызова: «применить + отменить» проверяются в одном скрипте.
- Ответы инструментов в файлы не сохраняются: данные из одного вызова для другого нужно записать в файл самому
  (Write), а не надеяться на временные файлы.
