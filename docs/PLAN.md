# Components Swapper — план

Плагин Figma: дизайнеры собирают макеты из разных старых библиотек; плагин переводит макет на компоненты и иконки
WB AID Rider/Driver с сохранением контента, а дальше предлагает новые компоненты и доработки существующих.

## Ограничения платформы

1. **Plugin API не перечисляет компоненты библиотеки** (`teamLibrary` — только переменные). Индекс собирается плагином
   в открытом файле библиотеки и хранится вне макета.
2. `importComponentByKeyAsync` импортирует только опубликованные компоненты.
3. `documentAccess: dynamic-page` — главный компонент экземпляра читается только `getMainComponentAsync()`.
4. `swapComponent` переносит оверрайды по совпадению имён слоёв; вложенные instance swap и привязки переменных могут
   сброситься (правила 12, 15, 28 скилла) — переносим сами.
5. Ключ ИИ в плагине не спрятать — ИИ только через сервер.

## Архитектура

```
├─ config/libraries.json   ← библиотеки компонентов и иконок: id, продукт, вид, fileKey
├─ src/
│  ├─ core/                ← без Figma, покрыто тестами; движок замены — только отсюда
│  ├─ figma/               ← индекс библиотеки, скан, замена через Plugin API
│  ├─ shared/messages.ts   ← sandbox ↔ UI
│  └─ ui/                  ← Preact
├─ server/                 ← (позже) Worker: индексы, прокси ИИ, предложения
└─ tests/                  ← vitest
```

Сопоставление без ИИ: имя (нормализация + синонимы), структурный отпечаток поддерева, `detachedInfo` у отвязанных
фреймов, перцептивный хэш растра (UI-iframe, canvas). ИИ — только этапы 4–5 (имена, описания, обоснования) и спорные
случаи.
